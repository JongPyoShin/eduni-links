# 의준이 서바이벌 — 고품질 게임 UI + Scenario 3D 에셋 전환 설계

## 사용자 피드백과 기준
- 문제: 현재 v0.8의 Canvas 도형 중심 캐릭터/월드가 장난감 수준으로 단순하며, 세로 화면에서는 콘텐츠가 과대 확대되어 조작까지 불편함.
- 목표: **스타일을 통일한 3D 동화책형 추격 게임**. 단지 HTML 버튼을 예쁘게 꾸미는 정도가 아니라 월드와 캐릭터를 바꿔야 최종 완성.
- 레퍼런스: https://huggingface.co/datasets/scenario-labs/3d-collection
- 공개 데이터 카드 기준 1,342 examples / 1,500 output files / 약 39 GB. GLB 1,271개, Blender 137개 등. **CC BY 4.0**, 출처 **Scenario** 표기. 원본 저작·표기 조건 및 개별 파일은 검증 후 적용. 이 컬렉션은 단일 게임용 통합 에셋팩이 아니라 서로 다른 모델과 스타일의 결과 모음이다.

## v1.0 UI 시안 (이번 브랜치, 배포 전)
기능은 수정 없이, 진행 중인 v0.9 모바일 카메라 개선을 바탕으로 **시각 언어**를 정비했다.

1. 월드 고르기: 각 월드의 고유 컬러/입체 레이어(정글: 초록, 북극: 얼음 블루, 피라미드: 모래 금색)로 커다란 포스터형 카드.
2. 탐험가·토끼 선택/목숨·모드: 같은 반투명/양각 카드 디자인, 선택 상태는 실선 테두리와 배지로 표시. 애니메이션 감소 설정 존중.
3. 게임: 선택 월드 테마만 UI CSS 변수로 전달. 물리·충돌·AI·지도 좌표·아이템과 독립.
4. 모바일: v0.9의 **세로 비율에 맞춘 논리 카메라**, 게임 아래 별도의 조작 도크. 상태 8칩 중 중복된 월드·열쇠 칩은 화면에서 숨기고, 나머지 우선순위 칩 재배치. 터치 버튼 44px 이상, 164px 이하의 펼친 레이더, safe-area.
5. 실제 게임 그리기: 여전히 2.5D Canvas 도형. 이번 버전에 3D GLB, WebGL 의존성, 거대한 외부 에셋을 넣지는 않았다. **이를 진짜 3D 버전이라고 소개하면 안 된다.**

## v1.1 WebGL 3D MVP 및 v1.2 Scenario GLB 마이그레이션 가이드
### 미술 컨셉
- 톤: **low-poly / soft-clay / storybook** 중 하나로 모든 에셋을 리토폴로지/재질 정리하고 통일. 실제 사진같은 고밀도 3D와 만화 캐릭터를 섞지 않음.
- 카메라: 정사영 또는 약한 원근의 탑다운 3/4. 모든 월드에서 안전한 시야, 캐릭터/출구/쉼터가 배경에 묻히지 않는 대비.
- 조명: 모바일 친화적인 단일 키라이트, 바닥의 부드러운 접촉 그림자, 가벼운 앰비언트.
- 애니메이션: 달리기/피격/숨기/성공에 동일한 모션 룰. 기초 움직임은 기존 `SurvivalLogic`이 authoritative.

### 에셋 검토 기준
- 자료형: GLB 우선. SPZ/Blender/FBX는 별도 변환 및 검증 필요.
- 에셋별 **폴리곤 수, 재질, 텍스처 해상도, draw calls, 축/스케일, 피벗, 바닥 접촉, 애니메이션 존재 여부** 점검.
- 과대 모델을 그대로 다운로드하지 않음. 샘플 GLB만 선별 받아 로컬 보관 후 Blender 등으로 decimate/atlas 압축, KTX2/Basis와 필요시 Draco/meshopt 검토. 배포된 결과가 CDN의 토큰 만료나 업스트림 파일 변경에 의존하지 않아야 함.
- 1차 목표: 모바일 전체 월드 텍스처·모델 전송량 예산 **8 MB 이하**, 중간급 Android에서 안정적 **30fps 이상**, 프레임/메모리 기준 실측 후 조정(확정 성능이 아님). WebGL 실패 시 기존 Canvas 모드로 폴백.
- 주인공/몬스터의 애니메이션이 없는 static GLB를 달리는 주인공으로 쓰지 않음. 필요시 리깅·모션 추가.

### 게임과 렌더러 분리
1. 2048×1536 가상 2D 월드, 적 AI/추격/은신/충돌/열쇠·출구 좌표와 게임 밸런스는 기존 `survival_static/logic.js`와 `worlds.js`에 둔다.
2. **Three.js/Babylon.js 렌더링 어댑터**에서 (x,y) 월드 좌표를 3D ground (x,0,z)로 사상. 플레이어·적·장애물·출구는 state를 읽어 렌더링만 수행한다. 물리/AI가 3D 드로어에 직접 의존하지 않음.
3. 모바일 DPR 제한, 그림자 품질 옵션, GPU 타이밍/프레임 점검, 월드별 lazy load. 뷰포트 비율/화면 안전 영역은 v0.9 계약을 준수.
4. 캐릭터와 환경 색상·스케일을 테스트 스크린샷으로 평가하고, 중간급 안드로이드/아이폰과 PC에서 실제 손가락 조작 검증.

## 릴리즈 게이트
- v1.0는 **UI 실험**과 2D 모바일 시야 수정이며, v1.1에는 별도의 WebGL 렌더러 구현을 추가했다. 사용자 실화면 검사 없이는 기존 공개 v0.8을 덮어쓰지 않음.
- v1.1은 실제 Three.js WebGL 렌더러로 월드·캐릭터·물체를 입체 메시로 표현하는 **가벼운 3D MVP**. 아직 Scenario GLB 파일은 넣지 않았고, 외부 Three.js 모듈을 불러오지 못하면 Canvas 2D로 복구.
- v1.2 이후 Scenario GLB 모델은 파일별 **크기/라이선스/기하·리깅/실기기 FPS 검증** 뒤 별도 PR로 적용. 검증되지 않은 대용량 HF URL을 곧바로 게임에 연결하지 않음.
- 기존 v0.9 PR #87은 `main`에 병합하지 않고 유지. v1.0 브랜치는 그 HEAD를 부모로 하여 모바일 수정이 누락되지 않음.
- 공개 게임 메인 링크와 가족 PC 운영 서버는 서로 별개. GitHub Pages 배포 및 서버 재기동은 사용자가 별도로 승인하는 시점에 구분해 검증.
