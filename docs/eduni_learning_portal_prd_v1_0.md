# 으듀니 학습 놀이터 확장 기획서

**문서 버전:** v1.0  
**작성일:** 2026-06-12  
**대상 저장소:** `JongPyoShin/eduni-links`  
**목적:** 기존 한자 중심 시험·게임을 유지하면서, 7세 전후 아동이 수학·언어·영어·사고력·창의성·기초 코딩·정서 표현을 재미있게 경험하는 가족용 학습 포털로 확장한다.  
**주요 독자:** 부모 기획자, CODEX 개발 에이전트, 향후 콘텐츠 작성자

## 0. 한 장 요약

이 포털은 온라인 문제집이 아니다. 아이가 **고르고**, **해 보고**, **설명하고**, **다른 방법을 발견하고**, **짧게 성공한 뒤 화면 밖 활동으로 이어지는** 디지털 학습 놀이터다.

기존 한자 콘텐츠는 `한자마을`로 유지한다. 신규 홈 화면에서는 `오늘의 탐험`을 중심으로 여러 학습 세계를 선택할 수 있게 한다. 초기 MVP는 과목별 진도표보다 **짧은 놀이형 활동**과 **부모용 관찰 화면**을 먼저 만든다.

### 핵심 설계 원칙

1. **정답형과 열린 탐구형을 함께 둔다.**  
   한자 읽기, 수 비교처럼 답이 명확한 활동과 이야기 만들기, 여러 해결법 찾기처럼 답이 하나가 아닌 활동을 균형 있게 배치한다.

2. **점수 경쟁보다 개인 성장 기록을 사용한다.**  
   외부 순위표, 친구 비교, 실패 벌점은 넣지 않는다. `끝까지 해봄`, `다른 방법 발견`, `설명해봄` 같은 과정 배지를 사용한다.

3. **짧게 끝나고 화면 밖으로 이어진다.**  
   기본 활동은 5~10분, 한 번의 탐험 묶음은 15분 이내로 설계한다. 종료 시 오프라인 미션을 하나 제안한다.

4. **빠른 인지 발달과 실패 회피 경향을 동시에 고려한다.**  
   쉬운 준비 문제로 시작하고, 힌트를 단계적으로 제공한다. 틀렸다는 경고보다 `다시 살펴볼까?`, `다른 길도 있어` 같은 표현을 사용한다.

5. **가족용 MVP에서는 개인정보 수집을 최소화한다.**  
   로그인 없이 로컬 또는 가족 서버에 저장하고, 음성·사진 원본은 기본 저장하지 않는다. 외부 광고, 외부 분석 SDK, 소셜 공유 버튼은 제외한다.

## 1. 현재 저장소 진단과 확장 방향

### 1.1 확인된 기존 자산

현재 저장소에는 이미 다음 자산이 있다.

| 기존 자산 | 재사용 방향 |
|---|---|
| `portal/index.html` 정적 프로토타입 | 공개 진입 화면으로 재사용. 내부 IP 하드코딩 제거 |
| `update_links.ps1` | 실행 중 서비스 URL을 읽어 리다이렉트와 포털 링크 설정을 갱신하도록 확장 |
| `hanja/index.html` | 기존 한자 서비스 진입 경로 유지 |
| 한자 급수 JSON과 생성 스크립트 | `한자마을` 콘텐츠 자산으로 유지 |
| `nice-gui-1-1-7/app.py` | 가족 서버 기반 동적 학습 앱의 출발점으로 활용 |
| 테트리스, 버블팝, 한자 슈터 | 자유 놀이 또는 집중 전환용 게임으로 유지 |
| 모바일 대응 UI와 터치 조작 | 신규 활동의 기본 UX 참고 |

### 1.2 구조적 문제

기존 앱은 큰 HTML·CSS·JavaScript 문자열이 한 파일에 포함된 부분이 있다. 소규모 게임에는 빠르지만, 학습 활동이 늘어나면 수정 범위가 커지고 테스트가 어려워진다.

신규 기능은 다음 원칙으로 분리한다.

- 공개 정적 런처와 가족 서버 동적 앱을 구분한다.
- 활동 메타데이터, 문제 데이터, UI 렌더러, 진행 기록, 추천 규칙을 분리한다.
- 활동 데이터는 가능한 한 `content/activities/**/*.json`에 둔다.
- 활동 목록은 레지스트리에서 자동으로 노출한다.
- 기존 `/hanja`, 테트리스, 버블팝, 한자 슈터 진입은 깨지지 않게 유지한다.
- `portal/index.html` 내부 IP 하드코딩을 제거한다.
- `update_links.ps1`가 `portal/config/links.json` 또는 동등한 설정 파일을 생성·갱신하도록 한다.

## 2. 대상 사용자와 개인화 방향

### 2.1 1차 대상

- 한국어를 주 언어로 사용하는 7세 전후 아동
- 유치원 마지막 단계에서 초등학교 입학 전후로 넘어가는 시기
- 글자, 숫자, 한자 패턴을 비교적 빠르게 이해하는 편
- `왜?`, `어떻게?` 질문과 규칙 찾기를 좋아함
- 찾기놀이, 이야기, 그림, 짧은 미션을 좋아함
- 칭찬과 성공 경험에 민감하고, 경쟁에서 지는 상황은 부담스러울 수 있음

### 2.2 UX 원칙

- 첫 화면에서 아이가 스스로 고를 수 있는 카드형 메뉴를 제공한다.
- 한 화면에 선택지는 4~6개 이내로 제한한다.
- 버튼은 모바일 터치를 고려해 충분히 크게 만든다.
- 활동 시작 후 30초 안에 첫 성공 경험을 제공한다.
- 연속 오답 시 난이도를 자동으로 낮추기보다 힌트를 먼저 제공한다.
- 활동 종료 시 점수보다 과정 중심 문구를 보여 준다.
- `틀렸어`, `실패`, `순위 하락`과 같은 표현은 피한다.
- 부모 화면은 아이 화면과 분리하고 PIN을 사용한다.

### 2.3 과정 칭찬 예시

- `끝까지 살펴봤구나!`
- `다른 방법도 찾아냈네!`
- `천천히 다시 본 게 멋져!`
- `왜 그렇게 생각했는지 말해볼까?`
- `한 번 더 도전해서 발견했네!`

## 3. 교육 설계 기준

### 3.1 발달 관점

7세 전후의 학습은 교과 문제를 많이 푸는 방식보다 놀이, 선택, 탐색, 표현, 반복 시도가 함께 있을 때 효과적이다. 따라서 포털은 다음 요소를 지원한다.

- **실행 기능:** 기억하기, 규칙 바꾸기, 차례 기다리기, 집중 유지
- **언어 표현:** 이유 말하기, 이야기 순서 만들기, 단어 분류하기
- **수학적 사고:** 수 감각, 비교, 패턴, 공간, 여러 해결 방법
- **창의성:** 정답이 하나가 아닌 과제, 조합, 이야기 만들기
- **정서 조절:** 힌트 사용, 재도전, 감정 이름 붙이기
- **디지털 균형:** 짧은 화면 활동 뒤 오프라인 미션 연결

### 3.2 국내 교육과정 연결 방향

콘텐츠는 학교 선행 경쟁을 목표로 하지 않는다. 다만 초등 입학 전후의 기초 역량과 자연스럽게 연결한다.

| 영역 | 연결 방향 |
|---|---|
| 국어 | 듣기·말하기, 낱말 의미, 문장 순서, 짧은 글 이해, 이야기 구성 |
| 수학 | 수 감각, 덧셈·뺄셈의 의미, 비교, 분류, 규칙, 도형과 공간 |
| 영어 | 소리 친숙화, 그림-단어 연결, 짧은 표현 듣기, 알파벳 인식 |
| 통합 탐구 | 관찰, 분류, 예측, 생활 속 과학 질문 |
| 사회·정서 | 감정 이름 붙이기, 선택 이유 말하기, 생활 습관 |
| 디지털 소양 | 순서, 조건, 디버깅, 안전한 사용 습관 |

## 4. 정보 구조

### 4.1 아이용 홈 `/portal`

첫 화면에는 다음을 배치한다.

1. `오늘의 탐험` 카드 1개
2. 학습 세계 카드 8개
3. `잠깐 놀이` 카드: 기존 테트리스, 버블팝, 한자 슈터
4. `오늘 발견한 것` 요약
5. 부모 화면 진입 버튼은 화면 하단에 작게 배치

### 4.2 학습 세계 `/portal/world/{world}`

| 세계 ID | 표시 이름 | 핵심 역량 | 초기 대표 활동 |
|---|---|---|---|
| `hanja` | 한자마을 | 형태·뜻·소리 연결, 어휘 | 한자 그림 탐정, 한자 짝 찾기 |
| `math` | 수학탐험대 | 수 감각, 패턴, 공간 | 보석 나누기, 규칙 기차 |
| `thinking` | 생각숲 연구소 | 관찰, 추론, 분류 | 탐정의 단서, 다른 것은 누구? |
| `korean` | 말글 공방 | 어휘, 이야기, 읽기 | 그림 순서 이야기, 낱말 바구니 |
| `english` | 영어 소리마을 | 듣기, 소리, 그림 연결 | 소리 듣고 동물 찾기, 알파벳 보물찾기 |
| `creative` | 창의 작업실 | 조합, 발상, 표현 | 이상한 발명품, 이야기 이어 붙이기 |
| `coding` | 로봇 코딩 놀이터 | 순서, 조건, 디버깅 | 로봇 길 찾기, 고장 난 명령 고치기 |
| `life` | 마음·생활 탐험 | 정서 표현, 습관, 안전 | 오늘의 기분 카드, 상황 선택 이야기 |

### 4.3 부모 화면 `/portal/parent`

- PIN 진입
- 최근 활동 기록
- 활동 시간과 중단 여부
- 힌트 사용 횟수
- 과정 배지 기록
- 선호 세계와 자주 선택한 활동
- 다음 활동 추천 이유
- 활동별 난이도 조정
- 화면 사용 시간 기본값
- 데이터 내보내기와 초기화

부모 화면에는 또래 비교, 등수, 종합 점수를 넣지 않는다.

## 5. 초기 활동 상세 명세

### 5.1 한자 그림 탐정

- **세계:** 한자마을
- **목표:** 그림, 뜻, 한자 모양을 연결한다.
- **흐름:** 그림과 짧은 이야기 제시 → 후보 한자 3개 → 선택 → 뜻과 소리 확인 → 비슷한 모양 한자 추가 탐색
- **난이도:** 후보 2개 → 3개 → 유사 형태 포함 4개
- **힌트:** 그림 강조 → 음 읽어주기 → 획 일부 강조
- **과정 배지:** `꼼꼼 탐정`, `다시 살펴봄`

### 5.2 한자 짝 찾기

- **목표:** 한자-뜻, 한자-음, 한자-그림을 연결한다.
- **흐름:** 카드 뒤집기 방식이지만 시간 제한은 기본 비활성화한다.
- **난이도:** 4쌍 → 6쌍 → 비슷한 한자 포함 8쌍

### 5.3 보석 나누기

- **세계:** 수학탐험대
- **목표:** 수의 분해와 합성을 놀이로 경험한다.
- **흐름:** 보석 N개를 두 상자에 나누기 → 서로 다른 방법 찾기 → 발견한 방법 수 표시
- **특징:** 답 하나를 맞히는 대신 여러 방법을 탐색한다.
- **예:** 7개를 `1+6`, `2+5`, `3+4` 등으로 나누기
- **과정 배지:** `다른 방법 발견`

### 5.4 규칙 기차

- **세계:** 수학탐험대
- **목표:** 반복 패턴을 관찰하고 다음 항목을 예측한다.
- **흐름:** 색·모양 기차 제시 → 빈칸 채우기 → 아이가 직접 규칙 만들기
- **난이도:** AB → AAB → ABC → 두 속성 조합
- **오프라인 연결:** 집 안 물건으로 반복 패턴 만들기

### 5.5 탐정의 단서

- **세계:** 생각숲 연구소
- **목표:** 조건을 하나씩 적용해 후보를 줄인다.
- **흐름:** 동물·탈것·물건 카드 제시 → `날개가 있어`, `물속에 살지 않아` 등 단서 제시 → 후보 선택 → 이유 말하기
- **난이도:** 조건 1개 → 2개 → 3개
- **과정 배지:** `이유를 설명함`

### 5.6 다른 것은 누구?

- **목표:** 분류 기준을 발견하고 자신의 기준을 설명한다.
- **특징:** 정답이 하나가 아닐 수 있다. 설명이 타당하면 인정한다.
- **예:** 사과, 바나나, 포도, 당근 중 다른 것 찾기. `당근은 과일이 아니야`, `바나나는 길쭉해` 등 다양한 설명 인정.

### 5.7 그림 순서 이야기

- **세계:** 말글 공방
- **목표:** 사건의 순서와 인과 관계를 말로 구성한다.
- **흐름:** 그림 3~4장 순서 배열 → 아이가 제목 선택 → 이유 말하기 → 부모와 함께 한 문장 만들기
- **저장 원칙:** 음성 원본은 기본 저장하지 않는다. 선택 결과와 완료 여부만 저장한다.

### 5.8 낱말 바구니

- **목표:** 단어를 기준에 따라 분류한다.
- **흐름:** 단어·그림 카드를 `먹는 것`, `타는 것`, `동물` 등 바구니에 넣기 → 새로운 분류 기준 만들기

### 5.9 소리 듣고 동물 찾기

- **세계:** 영어 소리마을
- **목표:** 짧은 영어 표현과 그림을 연결한다.
- **흐름:** `Find the cat`, `Touch the blue bird` 등 짧은 음성 → 그림 선택 → 천천히 다시 듣기
- **원칙:** 시험식 철자 암기보다 듣기와 친숙화를 우선한다.

### 5.10 알파벳 보물찾기

- **목표:** 알파벳 형태를 그림 속에서 찾는다.
- **흐름:** 장면 속 숨은 글자 찾기 → 대문자·소문자 짝 연결 → 해당 소리 듣기
- **개인화:** 찾기놀이 선호를 활용한다.

### 5.11 로봇 길 찾기

- **세계:** 로봇 코딩 놀이터
- **목표:** 순차 명령과 디버깅을 경험한다.
- **흐름:** 격자 지도 → 앞으로, 왼쪽, 오른쪽 블록 배치 → 실행 → 도착하지 않으면 한 단계씩 확인
- **난이도:** 3명령 → 장애물 → 반복 → 간단한 조건
- **과정 배지:** `차근차근 고침`

### 5.12 오늘의 기분 카드

- **세계:** 마음·생활 탐험
- **목표:** 감정을 이름 붙이고 이유를 짧게 표현한다.
- **흐름:** 표정 카드 고르기 → 이유 선택 또는 부모와 말하기 → 작은 회복 행동 하나 고르기
- **주의:** 평가·진단 기능이 아니다. 저장은 최소화한다.

## 6. 오늘의 탐험 추천 규칙

초기에는 AI 추천을 사용하지 않는다. 설명 가능한 규칙 기반으로 충분하다.

### 6.1 기본 탐험 묶음

한 묶음은 10~15분 내외다.

1. 준비 활동 1개: 쉬운 성공 경험, 2~3분
2. 핵심 활동 1개: 현재 수준에 맞춘 활동, 5~8분
3. 선택 놀이 또는 화면 밖 미션 1개: 2~5분

### 6.2 추천 규칙 예시

- 최근 3회 동안 같은 세계만 선택했다면 다른 세계를 한 개 추천한다.
- 연속 중단이 2회 이상이면 준비 활동 난이도를 낮춘다.
- 힌트를 사용한 뒤 완료했다면 실패로 기록하지 않는다.
- 같은 활동을 좋아하면 반복을 허용하되, 세 번째 반복부터 작은 변형을 제공한다.
- 늦은 시간에는 자극적인 자유 게임보다 짧은 이야기·분류 활동을 추천한다.

### 6.3 난이도 조절

난이도는 `easy`, `normal`, `challenge` 3단계로 시작한다.

- 첫 진입은 `easy`
- 최근 3회 중 2회 이상 힌트 없이 완료하면 다음 단계 제안
- 연속 2회 중단 또는 반복 힌트 사용 시 이전 단계 제안
- 자동 변경보다 부모 화면 또는 아이 선택을 우선
- 도전 단계는 보너스이며 필수 진도가 아니다

## 7. 화면 설계

### 7.1 아이용 홈 화면

- 상단: `오늘은 무엇을 탐험할까?`
- 첫 카드: `오늘의 탐험 시작`
- 그 아래: 2열 또는 3열 세계 카드
- 각 카드: 아이콘, 이름, 한 줄 설명, 최근 과정 배지
- 하단: `잠깐 놀이`, `오늘 발견한 것`
- 모바일에서는 1열 또는 2열로 자연스럽게 축소

### 7.2 활동 화면 공통 구성

- 상단 왼쪽: 뒤로 가기
- 상단 가운데: 활동 이름
- 상단 오른쪽: 소리 켜기·끄기
- 중앙: 핵심 놀이 공간
- 하단: 힌트, 다시 보기, 완료
- 결과 화면: 과정 칭찬, 발견한 것, 화면 밖 미션

### 7.3 접근성과 안전

- 터치 영역 최소 높이 44px 이상
- 텍스트만으로 상태를 전달하지 말고 아이콘과 함께 사용
- 소리 끄기 제공
- 자동 재생 소리는 최소화
- 외부 링크는 아이 화면에서 직접 노출하지 않음
- 부모 화면은 PIN 뒤에 배치

## 8. 데이터 모델 초안

### 8.1 활동 JSON 스키마

```json
{
  "id": "math.pattern_train.001",
  "world": "math",
  "title": "규칙 기차",
  "activity_type": "pattern_sequence",
  "difficulty": "easy",
  "estimated_minutes": 5,
  "skills": ["pattern", "observation", "explanation"],
  "curriculum_tags": ["math.pattern.basic"],
  "prompt": "다음 칸에는 어떤 모양이 올까?",
  "items": [],
  "hints": [
    "같은 순서가 다시 나오는지 살펴보자.",
    "앞에서부터 천천히 읽어보자."
  ],
  "process_badges": ["retry", "explain", "new_method"],
  "offline_mission": "집 안 물건 세 가지로 규칙을 만들어 보자.",
  "enabled": true,
  "version": 1
}
```

### 8.2 Pydantic 모델 요구사항

`Activity` 모델은 최소한 다음을 검증한다.

- `id`는 중복되지 않는다.
- `world`는 등록된 세계 ID 중 하나다.
- `difficulty`는 허용된 값이다.
- `estimated_minutes`는 1~15분 범위다.
- `hints`는 최대 3개다.
- `enabled` 기본값은 `true`다.
- 개인정보 수집 필드가 콘텐츠에 포함되지 않는다.

### 8.3 SQLite 테이블 초안

```sql
CREATE TABLE child_profile (
  id INTEGER PRIMARY KEY,
  display_name TEXT NOT NULL,
  created_at TEXT NOT NULL,
  active INTEGER NOT NULL DEFAULT 1
);

CREATE TABLE activity_session (
  id INTEGER PRIMARY KEY,
  child_profile_id INTEGER NOT NULL,
  activity_id TEXT NOT NULL,
  difficulty TEXT NOT NULL,
  started_at TEXT NOT NULL,
  completed_at TEXT,
  completed INTEGER NOT NULL DEFAULT 0,
  hint_count INTEGER NOT NULL DEFAULT 0,
  retry_count INTEGER NOT NULL DEFAULT 0,
  result_summary_json TEXT,
  FOREIGN KEY(child_profile_id) REFERENCES child_profile(id)
);

CREATE TABLE process_badge_event (
  id INTEGER PRIMARY KEY,
  activity_session_id INTEGER NOT NULL,
  badge_code TEXT NOT NULL,
  created_at TEXT NOT NULL,
  FOREIGN KEY(activity_session_id) REFERENCES activity_session(id)
);

CREATE TABLE parent_settings (
  id INTEGER PRIMARY KEY,
  pin_hash TEXT NOT NULL,
  daily_screen_minutes INTEGER NOT NULL DEFAULT 20,
  sound_enabled INTEGER NOT NULL DEFAULT 1,
  updated_at TEXT NOT NULL
);
```

### 8.4 저장하지 않는 데이터

초기 버전에서는 다음을 저장하지 않는다.

- 아이 사진 원본
- 아이 음성 원본
- 위치 정보
- 외부 광고 식별자
- 외부 분석 SDK 이벤트
- 소셜 로그인 정보
- 공개 프로필
- 다른 아이와의 비교 데이터

## 10. 개발 단계

## 12. CODEX 작업 규칙

CODEX는 한 번에 전체 포털을 구현하지 않는다.

1. 먼저 저장소를 분석한다.
2. 변경 파일 목록을 제시한다.
3. 기존 기능 호환성 유지 방안을 설명한다.
4. Phase 0만 구현한다.
5. 테스트를 실행한다.
6. 변경 파일, 실행 명령, 테스트 결과, 남은 위험을 보고한다.
7. Phase 1은 별도 지시가 있을 때 시작한다.

### 금지 사항

- 기존 한자 콘텐츠 삭제
- 기존 게임 경로 무단 변경
- 대규모 프레임워크 교체
- 외부 분석 SDK 추가
- 광고 추가
- 공개 계정 생성
- 아이 사진·음성 저장
- 위치 접근
- 순위표와 또래 비교
- 전체 기능을 한 번에 구현

## 14. 참고 방향

향후 콘텐츠를 늘릴 때는 문제 수를 빠르게 늘리는 것보다, 각 활동의 재미와 반복 가능성을 먼저 확인한다. 부모는 아이가 오래 앉아 있었는지가 아니라 어떤 활동을 골랐고, 힌트를 어떻게 사용했고, 다시 시도했는지를 관찰한다.

첫 번째 구현 목표는 화려한 완성품이 아니다. **기존 한자 포털을 안전하게 유지하면서 새로운 학습 세계를 하나씩 추가할 수 있는 구조**를 만드는 것이다.
