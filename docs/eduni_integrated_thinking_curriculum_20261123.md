# EDUNI 통합형 사고력 교육·콘텐츠 방향 보고서
**버전:** v1.0 · **작성:** 2026-11-23 · **상태:** 교육 방향 확정 / 1차 MVP 착수
**대상:** 가족 포털의 7~9세 아동(확장: 4~18세) 및 보호자

## 1. 목표와 배경
AI가 정답·정보 탐색 비용을 낮추더라도, 아이는 주어진 현상에서 문제를 발견하고 중요도를 판단하며 해결책을 검증해야 한다. 기존 독서·언어·수학·과학 기초 학습을 대체하지 않고, 해당 지식을 실제 상황에 적용하도록 **문제 발견 → 문제 정의 → 대안 생성 → 실험/검증 → 성찰 → 전이** 순환을 반복한다.
- **문제 발견:** 불편과 궁금증을 스스로 찾아 말한다.
- **문제 정의:** 관찰 사실과 추측을 구분하고 성공 기준을 제시한다.
- **대안 생성:** 정답 하나에 고착되지 않고 다양한 해결책을 낸다.
- **실행·검증:** 조건을 비교하고 실험·관찰로 근거를 찾는다.
- **자기주도:** 목표·활동·재시도 시점을 선택한다.
- **성찰·협력:** 생각이 달라진 이유를 설명하고 다른 입장을 존중한다.

**교육 원칙:** 정답률·순위·실패 벌점보다 과정의 증거를 기록한다. '문제해결 능력'은 모든 영역에 자동 전이되지 않으므로 국어·수학·과학·사회 활동과 명시적으로 연결한다. 무조건적 발견학습 대신 짧은 시범·힌트·발판(scaffolding)과 자유 탐색을 함께 제공한다.

## 2. 발달 단계
| 연령(유연한 기준) | 핵심 목표 | 대표 콘텐츠 | 보호자의 역할 |
|---|---|---|---|
| 4~6세 | 관찰·호기심·놀이 | 분류, 원인 추측, 블록 놀이 | 함께 놀며 표현 지원 |
| **7~9세(우선)** | 간단한 문제 정의·대안·실험 | 종이 다리, 그림 속 불편, 동화의 선택, 가족 문제 | 질문 코치, 필요할 때만 힌트 |
| 10~12세 | 원인 분석·제약 아래 설계 | 예산, 시간표, 조사 프로젝트 | 자료 지원, 판단은 아이에게 |
| 13~15세 | 관점·근거·부작용 검토 | 이해관계자 비교, 데이터 검증 | 토론 상대 |
| 16~18세 | 자기 목표의 장기 프로젝트 | 실제 사용자 문제·제작·평가 | 멘토, 안전 점검 |

연령이 아닌 실제 언어·인지·정서 발달과 흥미에 따라 난이도를 조정한다. 부담이 생기면 문제 수가 아니라 과제 난이도와 힌트 수준을 조정한다.

## 3. 콘텐츠 유형과 첫 12주
1. **문제 탐정단:** 그림/생활 속 문제를 발견하고 현상과 원인을 구분한다.
2. **발명 연구실:** 과학·수학 개념을 도구로 사용해 만들고 검증한다.
3. **이야기 법정:** 독서 내용의 여러 입장·근거·결과를 논한다.
4. **우리집 프로젝트:** 가족과 협력해 실제 불편을 개선한다.

- **1~4주(생활):** 불편 찾기 → 문제 하나 정의 → 방법 둘 비교 → 바꾼 점 기록.
- **5~8주(자연):** 현상 관찰 → 가설 둘 → 조건을 맞춘 실험 → 예측 재검토.
- **9~12주(사람):** 타인 의견 듣기 → 이해 충돌 찾기 → 공동 해결책 → 피드백 반영.
- 각 주는 화면 5~10분의 질문·예측 + 화면 밖 탐구 15~30분 + 3~5분 성찰을 **예시**로 제시한다. 활동 시간은 아이의 몰입·피로도에 따라 줄이거나 중단한다.

## 4. 콘텐츠 데이터 규약(초기)
각 미션은 `id, title, category, estimated_minutes, skills, offline_task, steps`로 구성한다.
- `steps`: **발견/정의/대안/실험/성찰**의 다섯 단계, 단계마다 이해 가능한 질문과 2~4개의 선택지를 제시.
- 선택지는 **정답이 아닌 사고의 출발점**이다. 어떤 선택도 틀렸다고 표시하지 않는다.
- 최소 한 단계는 직접 실험/만들기/역할놀이를 요구하고, 마지막 단계에서 예상과 실제 결과의 차이를 성찰한다.
- 텍스트가 짧고 버튼이 큰 모바일 우선 디자인. 활동 도중 종료·복귀할 수 있어야 한다.
- 향후 개방형 서술/음성·사진 수집은 **기본 비활성**. 아동이 직접 LLM과 자유 대화하는 기능은 1차 범위에서 제외.

### MVP 권장 미션(6개 중 초기 구현은 2개)
| ID | 영역 | 교육 장면 |
|---|---|---|
| paper_bridge | 발명 연구실 | 종이 다리의 강도를 예측·실험·수정 |
| playground | 문제 탐정단 | 여러 불편 중 무엇이 문제인지 결정하고 의견 비교 |
| story_choice | 이야기 법정 | 이야기 인물의 선택을 다른 시선에서 검토 |
| tidy_room | 우리집 프로젝트 | 정리의 어려움을 정의하고 방법 비교 |
| dry_leaves | 발명 연구실 | 낙엽이 마르는 원인을 관찰·가설·비교 |
| family_queue | 우리집 프로젝트 | 가족 공용 물건 사용 규칙 협의 |

## 5. 사용자 경험
- **아이 홈:** '생각탐험 연구소' → 미션 선택 → 5단계 탐험 → 실제 활동 → 성찰 완료. 자유롭게 선택하고 중단할 수 있다.
- **부모 화면:** 기존 PIN 보호 화면에서 미션 진행·완료와 선택/재도전/성찰 등 간단한 관찰 근거 확인. 숫자는 평가등급이나 지능진단으로 해석하지 않는다.
- **칭찬:** '왜 그렇게 생각했는지 이야기해 보자', '새로운 방법을 발견했구나' 등 과정 중심.
- **AI 2차 도입:** 보호자가 조작하는 질문 코치. 정답 대행·자동 성격 평가·근거 없는 발달 진단 금지. AI 없이도 완전한 미션 경험이 동작해야 한다.

## 6. 구현 범위·기술 전략
기존 `JongPyoShin/eduni-links`의 NiceGUI `/portal`, `/portal/parent`, SQLite 프로필, PIN 보호, 게임 진입을 보존한다.
**1차(현재 브랜치):** 보고서, 독립 미션 콘텐츠 JSON 2개, 생각탐험 페이지·모바일 5단계 선택, 중간 저장/재개·완료, PIN 뒤 부모 요약 표시 및 관련 테스트.
**2차:** 6개 미션 완성, 12주 큐레이션, 독서·수학·과학 진입 연계, 관찰 카드.
**3차:** 보호자 주도 AI 질문 제안 및 추천. 실제 관찰 로그를 바탕으로 부모가 최종 승인.

기존 콘텐츠 검증과 기록 모델을 가능한 한 재사용하되, 프로젝트형 다단계 기록은 별도 최소 테이블로 격리한다. SQLite 갱신은 단일 트랜잭션·수정 버전 확인으로 중복 탭 충돌을 조용히 덮어쓰지 않는다.

## 7. 안전·검증·출시 정책
- 개인정보 최소화: 로그인 계정 확장, 광고·외부 분석, 카메라/마이크, 원본 사진·음성, 위치 수집 금지. 아동 답안은 선택지 번호만 저장.
- 부모 PIN을 우회하는 부모 조회 API나 공개 링크를 만들지 않는다.
- 필수 검증: 콘텐츠 구조·중복/오류, 미션 단계 경계, 완료/복귀, 저장 충돌 방지, 아동 프로필별 격리, 부모 PIN 뒤 노출, 기존 `/portal` 및 게임 진입 회귀.
- 임상 심리검사나 IQ/성격/장애 진단으로 사용하지 않는다.
- 병합/운영 배포는 별도 승인 및 실제 가족 PC 환경 확인 후 진행.
