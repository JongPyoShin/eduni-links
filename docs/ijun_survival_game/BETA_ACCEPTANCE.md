# 의준 서바이벌 베타 v0.1 — 적용 및 인수검증

## 구현 범위

- 독립 게임 주소: `/survival` (`/survival/`도 지원)
- EDUNI 가족 서버 포털 `/portal`의 **빠른 시작** 목록에 '마주치지 마! 서바이벌' **베타** 카드 추가
- 첫 번째 **정글 맵**, 위에서 내려다보는 2D 자유 이동
- 캐릭터 **탐험가/토끼** (동일 속도), 시작 목숨 **1~35개** 직접 선택
- 원숭이 2마리(수평 순찰), 뱀 1마리(수직 순찰)
- 나무 장애물, 출구, 선택적 별 3개, 시간, 점수 보상
- 적에게 부딪히면 목숨 -1, 1.5초 연속 피격 방지, 남은 목숨 0이면 게임 종료
- 출구 도달 시 승리, 즉시 재도전/목숨·캐릭터 변경
- 키보드 방향키/WASD와 터치 방향 패드, 일시정지/재개/탭 비활성 시 자동 중지
- 외부 에셋·API 요청·계정·분석 추적·아동 데이터 전송 없음

## 중요: 개발 브랜치 상태

이 코드는 기능 브랜치에만 있습니다. **main 병합 또는 실서버 배포는 실행하지 않았으며, 지금 라이브 주소에서 플레이 가능하다고 보증할 수 없습니다.**
`/jungle`, `/link`, `/omok`, `/bubble`, `/bubble-shooter`, `/` 등 기존 게임 경로와 구현은 그대로 유지했습니다.

## 개발 환경 실행 / 검증

브랜치를 체크아웃한 별도 개발 작업트리에서 다음 명령 수행. 현재 서버의 사용자 SQLite·설정·기타 작업트리는 변경하지 말 것.

```powershell
cd nice-gui-1-1-7
node --test tests/test_survival_logic.cjs
python scripts/validate_content.py
python -m unittest discover -s tests
cd ..
git diff --check
```

서버를 테스트 포트에서만 기동하고 `http://<테스트호스트>:<포트>/survival` 및 `/portal`을 확인한다.
같은 앱에서 `/jungle`, `/link`, `/omok`, `/bubble`, `/bubble-shooter`, `/` GET smoke를 수행한다.

## 테스트 범위 및 현재 증거

브랜치 내 게임 룰 코드를 격리 실행하여 경계값, 점수 배수, 장애물, 적 순찰/반전, 충돌/무적, 출구 경로(BFS)를 확인했다. 브라우저 코드의 DOM/Canvas 모의 객체를 이용한 시뮬레이션에서 시작→렌더링→일시정지→재개→터치→재시작→설정 복귀와, 1목숨 패배 및 출구 승리 상태를 확인했다.

**아직 안 한 것:** 실제 Node 명령 실행 로그, Python 전체 unittest, 운영/개발 서버 부팅·HTTP 200 응답, 실제 모바일/PC 브라우저 터치 실사용 검증. 이러한 항목은 실제 실행 전까지 PASS로 표기하지 않는다.

## 사용자 인수 체크리스트

- [ ] 1/5/15/35개 선택이 시작 HUD에 정확히 표시됨
- [ ] 탐험가·토끼 모두 움직이고, 키보드 및 터치 방향패드가 반응
- [ ] 나무를 뚫고 이동할 수 없음
- [ ] 원숭이/뱀에 닿으면 목숨 1개만 감소하며 1.5초 중복 감점 없음
- [ ] 1개 목숨에서 피격 시 결과 화면, 35개에서 34개로 감점
- [ ] 일시정지 중 적·타이머 정지, 다시 시작 시 초기 상태
- [ ] 출구에 닿으면 성공, 별 0개라도 출구 진입 가능
- [ ] 모바일 세로 화면에서 방향버튼/복귀/일시정지 클릭 가능
- [ ] 기존 포털과 운영 중인 게임들이 동일하게 동작
