# EDUNI 스도쿠 탐험 — 7세 모바일 게임 설계

## 목적과 범위

7세 아이가 혼자 시작해서, 막히면 도움을 받고, 중단했다가 이어 풀 수 있는 숫자 퍼즐이다.
계산 속도나 타인과의 경쟁을 평가하지 않는다. 성별에 따른 난이도는 나누지 않는다.
첫 릴리스는 4×4와 6×6이며 표준 9×9는 모바일 터치 사용성을 확인한 후 검토한다.
광고, 랭킹, 시간제한, 계정 생성, 아이 개인정보 수집, 네트워크 기록 전송은 없다.

## 규칙과 난이도

| 단계 | 판 | 구역 | 생성 목표 | 경험 |
| --- | --- | --- | --- | --- |
| `starter` 연습 | 4×4, 1–4 | 2×2 | 시작 숫자 약 10개 | 한 칸의 빠진 숫자 찾기 |
| `explorer` 탐험 | 4×4, 1–4 | 2×2 | 시작 숫자 약 7개 | 행·열·구역을 함께 보기 |
| `challenge` 도전 | 6×6, 1–6 | 2×3 | 시작 숫자 약 19개 | 더 큰 판에서 같은 규칙 쓰기 |

시작 숫자 수는 목표값이다. 생성기는 숫자를 하나 지울 때마다 **해답 하나**와
**단일 후보 또는 한 구역의 유일한 자리만으로 완주 가능**한지 확인한다.
조건을 잃으면 숫자를 되돌린다. 따라서 정해진 숫자 수를 만들지 못하면
검증을 통과한 조금 쉬운 판을 사용한다. 임의 추측을 요구하지 않는다.

완료한 같은 단계의 최근 두 판 모두 힌트 1회 이하, 충돌 2회 이하이면 다음 단계를
추천한다. 최근 두 판 모두 힌트 3회 이상이면 이전 단계를 추천한다.
추천은 다음 판에만 적용하고, 아이가 언제든 단계 버튼으로 직접 선택할 수 있다.
히스토리 비교에 다른 단계의 기록은 섞지 않는다.

## 핵심 플레이

1. 첫 방문은 `starter` 판을 바로 연다. 이후 방문은 브라우저에 저장된 판을 이어 연다.
2. 빈칸을 터치하면 해당 행, 열, 구역을 강조한다. 아래 큰 숫자 버튼으로 입력한다.
3. 맞지 않는 숫자를 넣으면 해당 칸을 부드럽게 표시하고, 되돌리기/지우기를 제공한다.
   7세 기본 모드에서는 중복이 없는 오답도 바로 재검토할 수 있다.
4. 힌트는 `살펴볼 칸 선택 → 행·열 관찰 안내 → 한 칸 답 채우기` 순서로 제공한다.
   오답이 이미 있으면 먼저 그 칸을 재검토하도록 안내한다.
5. 모든 칸이 정답이면 완료 카드와 다음 추천 단계를 표시한다.

`localStorage`의 `eduni-sudoku-v1`에는 현재 퍼즐, 입력값, 최근 되돌리기 기록 최대 30개를,
`eduni-sudoku-recent-v1`에는 최근 완료 결과 최대 6개만 저장한다.
서버 DB, 프로필, 기기 식별자에는 기록하지 않는다. 저장이 불가능한 브라우저에서도
현재 열린 판은 계속 플레이할 수 있다.

## UI 규칙

- 모바일 세로 화면을 우선한다. 360×800에서 가로 넘침 없이 보드, 숫자 버튼,
  기본 조작이 쉽게 보이고 눌려야 한다.
- 보드는 4×4·6×6 모두 가로/세로 정사각형이다. 구역 경계는 내부선보다 확실히 굵고
  가장자리 테두리 두께는 모든 변에서 균일해야 한다.
- 시작 숫자, 직접 입력한 숫자, 선택 칸, 충돌 칸은 색과 테두리/상태를 함께 사용해 구분한다.
- 숫자 입력은 드래그가 아니라 `칸 선택 → 숫자 선택`이다. `되돌리기`, `지우기`, `힌트`
  세 버튼만 플레이 중 전면에 둔다.
- 6×6 입력 버튼은 큰 타깃을 유지할 수 있도록 3열 2행이다.
- 포털 복귀, 난이도 전환, 새 퍼즐은 아이가 실수로 누를 수 있으므로 명확한 확인 문구를 사용한다.
  마지막 두 동작의 확인은 네이티브 브라우저 대화상자보다 페이지 내부 UI가 좋다.
- 실패 문구는 아이를 평가하지 않고 다음 행동을 알려준다. 애니메이션은 줄이기 설정을 따른다.

## 구현 경계

- `nice-gui-1-1-7/portal_app/static_games/eduni_sudoku_core.js`: 보드 생성, 규칙,
  유일해, 논리적 풀이, 힌트, 추천 단계. DOM 의존 없음.
- `nice-gui-1-1-7/portal_app/static_games/eduni_sudoku.html`: 화면과 로컬 상태.
- `nice-gui-1-1-7/portal_app/routes.py`: `/sudoku`와 포털 카드, core.js 정적 경로.
- `nice-gui-1-1-7/tests/test_sudoku_core.js`, `test_sudoku_route.py`: 작은 회귀 검증.

Luna는 시각적 마감과 간단한 화면 조작 개선만 담당한다.
핵심 생성·풀이·추천 규칙은 Main이 소유하며, 변경이 필요하면 근거를 보고한다.

### 퍼즐 생성과 상태 계약

`generate(level)`은 `{level, puzzle, solution}`을 반환한다. `puzzle`과 `solution`은
행 우선 1차원 숫자 배열이며 빈칸은 `0`이다. 기본 완성판을 숫자·행 묶음·열 묶음
순열로 섞은 뒤, 칸을 하나씩 지워 매번 `countSolutions(...) === 1`과
`logicSolvable(...) === true`를 검사한다. 생성이 목표 시작 숫자 수를 맞추지
못해도 검증을 통과한 판만 반환한다.

화면 상태는 `puzzle`(수정 불가 시작 숫자), `solution`(완료·친절한 오답 안내),
`entries`(현재 입력), `selected`, `hints`, `mistakes`, `completed`, `undo`로 구성한다.
아이의 입력은 `entries`만 수정한다. 완료 판정은 모든 칸이 `solution`과 일치할 때다.
힌트는 현재 입력에 오답이 있으면 먼저 그 칸을 가리키고, 정답을 자동으로 덮지 않는다.
브라우저 새로고침 때 저장 배열 길이·숫자 범위·시작 숫자 불변성과 완성판 규칙을 확인한다.

화면 변경은 `render()` 한 곳에서 그리며 사용자 조작 뒤 `save()`를 호출한다.
퍼즐 생성과 규칙 판정에는 DOM이나 네트워크 의존성이 없어서 Node 단독 검증이 가능하다.

## 수용 기준

1. 4×4와 6×6을 여러 시드로 만들 때 모두 유일해이며 논리적으로 풀린다.
2. 힌트, 충돌 표시, 지우기, 되돌리기, 완료 판정, 다음 단계 추천이 실제 브라우저에서 동작한다.
3. 새로고침 후 현재 판, 입력값, 최근 되돌리기 기록이 유지된다. 오염된 저장값은 새 판으로 복구된다.
4. 360×800, 390×844, 412×915 화면에서 가로 넘침과 잘린 핵심 버튼이 없다.
5. `/portal` 카드와 `/sudoku`, `/sudoku-assets/eduni_sudoku_core.js`가 정상 응답한다.
6. 기존 포털·게임 경로 회귀검사가 통과한다.

## 현재 1차 검증과 남은 확인

- Node 퍼즐 규칙 검증: 세 단계, 단계당 12개 시드, 유일해·논리 풀이 PASS.
- Python 라우트/포털 집중 테스트: PASS.
- 실제 Chrome: 4×4 힌트 3단계, 되돌리기, 새로고침 후 이어하기, 직접 클릭 완주 PASS.
- 실제 Chrome: 360px 뷰포트에서 4×4 가로 넘침 없음.
- 6×6 모바일 레이아웃, 네이티브 확인창을 통한 전환, 아이 직접 사용성은 후속 QA가 필요하다.
