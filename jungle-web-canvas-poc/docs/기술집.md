# Jungle 기술집

Jungle Web Game 개발 중 발견한 외부 기술/오픈소스 아이디어를 **그대로 복사하지 않고, 현재 구조에 맞게 선별 적용하기 위한 기술 참고 노트**다.

기본 원칙:

- 현재 검증된 gameplay / logical X/Y / geometry contract를 우선한다.
- 외부 프로젝트의 전체 아키텍처를 들여오기보다 **가치 있는 알고리즘·표현·패턴만 선택적으로 도입**한다.
- 새 dependency는 실제 효과가 분명할 때만 추가한다.
- Android WebView / 저사양 태블릿을 고려한다.
- 성능 수치는 추측하지 않고 profile-first로 판단한다.
- 도입 전 작은 PoC → 실제 플레이 체감 확인 → 본 적용 순서를 따른다.

## 1. Jakubantalik/thinking-orbs

- Repository: https://github.com/Jakubantalik/thinking-orbs
- Homepage: https://orbs.jakubantalik.com
- License: MIT
- 기술: TypeScript, 2D Canvas 기반 애니메이션
- 용도: AI/agent UI용 dotted thought-orb loading / state indicator
- 상태: `working`, `searching`, `solving`, `listening`, `connecting`, `weaving`, `composing`, `breathing`, `shaping`
- 기본 크기 preset: 64px / 20px

### 핵심 구조

기본 `ThinkingOrb` 컴포넌트는 React 기반이지만, 별도 `thinking-orbs/engine` entry point가 있다.

`thinking-orbs/engine`은:

- React 의존 없음
- DOM 의존 없음
- 순수 geometry/frame 계산
- frame마다 최종 `dots` / `lines` 데이터를 반환
- Canvas, OffscreenCanvas, React Native Skia, custom renderer 등에 연결 가능

따라서 Jungle에는 React 컴포넌트 전체를 가져오기보다 **engine만 활용하거나 동일한 아이디어를 vanilla JS로 얇게 포팅**하는 방향이 적합하다.

### Jungle 적용 판단

**판정: ADOPT NOW — 단, 전체 라이브러리 UI가 아니라 선택적 효과 시스템으로 사용**

Jungle의 핵심 렌더러는 그대로 Three.js/WebGL을 유지한다.
Thinking Orbs는 월드 렌더러를 대체하지 않고 다음과 같은 **HUD / 상호작용 / 포획 연출 보조 효과**로 사용한다.

| Jungle 상태 | Thinking Orbs 상태 | 적용 아이디어 |
|---|---|---|
| 평상시 탐험 | `breathing` | 탐험 감지기 idle |
| 단서 근처 | `searching` | 근처에 단서가 있음을 표시 |
| 새소리 / 소리 단서 | `listening` | 청각 탐색 상태 |
| 퀴즈 진행 | `solving` | 문제 풀이 상태 |
| 여러 단서 연결 | `connecting` | 흔적 연결 연출 |
| 포획 시작 | `weaving` | 새 주변 에너지 / 관찰 집중 |
| 포획 성공 | `shaping` → `composing` | 성공 → 도감 등록 전환 |
| 도감 등록 | `connecting` | 새 정보가 도감에 저장되는 연출 |

### 가장 먼저 적용할 위치

#### 1순위 — 새 포획 Quiz

플레이 루프:

```text
새 발견
  ↓
searching
  ↓
문제 시작
  ↓
solving
  ↓
2/3 이상 성공
  ↓
weaving → shaping
  ↓
포획 성공
```

현재 Jungle에서 부족한 "새를 잡았다"는 손맛과 시각 피드백을 강화하는 데 가장 효과가 크다.

#### 2순위 — 도감 등록

```text
새 portrait
  ↓
connecting orb
  ↓
도감 카드 공개
```

#### 3순위 — 탐험 HUD

작은 오브를 하나만 유지하고 상황에 따라 상태를 변경한다.

```text
평상시      breathing
단서 근처   searching
새소리      listening
문제         solving
```

단순 loader가 아니라 **탐험 감지기**라는 게임 시스템으로 해석한다.

### 렌더링 방식

#### Phase A — 가장 빠른 PoC

별도 작은 2D Canvas overlay.

```text
Three.js World
    │
    ├─ 기존 gameplay
    ├─ 기존 EffectSystem
    └─ Thinking Orb Canvas Overlay
```

장점:

- Three.js gameplay/rendering 변경 최소화
- 실패해도 쉽게 제거 가능
- 태블릿 성능 비교가 쉬움
- 기존 HUD에 독립적으로 붙일 수 있음

#### Phase B — Three.js 월드 통합

효과가 검증된 이후에만 검토한다.

```text
Thinking Orb Engine
       ↓
OffscreenCanvas
       ↓
THREE.CanvasTexture
       ↓
THREE.Sprite / Plane
```

이를 이용하면 단서, 새, 도감 포인트 근처에 실제 3D 월드 오브처럼 띄울 수 있다.

### Jungle 스타일 변형

원본은 monochrome AI UI 디자인이므로 그대로 사용하면 게임보다 AI loader처럼 보일 수 있다.

원본 알고리즘을 유지하되 Jungle 테마에 맞게 색/입자 느낌을 바꾼다.

예시:

- Camp: 연두 / 노랑
- Waterfall: 청록 / 하늘
- Cave: 보라 / 연두
- Giant Tree: 금색 / 초록
- Sky Ridge: 하늘 / 별빛

원본의 `dots` / `lines` geometry만 사용하고 최종 색은 Jungle renderer가 결정하는 방향을 우선한다.

### 성능 / 접근성 참고

thinking-orbs 원본 구현의 좋은 패턴:

- plain 2D canvas
- WebGL/filter 불필요
- DPR cap 2
- `prefers-reduced-motion` 대응
- offscreen 시 `IntersectionObserver`로 pause
- hidden tab에서 animation pause

Jungle에 적용할 경우에도 이 원칙은 참고할 가치가 있다.

특히 태블릿에서는 항상 animate하지 말고 **필요한 순간에만 활성화**하는 것을 우선한다.

### 하지 않을 것

현재 단계에서는 다음을 하지 않는다.

- React 추가
- Thinking Orbs가 Three.js renderer를 대체
- 기존 particle/effects 전체 교체
- 9개 상태 전부 사용
- 화면 곳곳에 여러 orb 인스턴스 생성
- gameplay geometry와 orb geometry 결합
- Orb 도입 때문에 stage progression 변경

초기에는 `searching`, `listening`, `solving`, `connecting`, `shaping` 중심으로 4~5개 상태만 사용한다.

### 구현 후보 파일

PoC 예시:

```text
src/effects/thinking_orb.js
src/effects/thinking_orb_presets.js
```

또는 npm package를 실제 도입할 경우:

```text
thinking-orbs/engine
```

단 현재 프로젝트는 vanilla ES module + Three.js 구조이므로 **React peer dependency 경로는 사용하지 않는다.**

### 적용 게이트

다음 순서로 판단한다.

1. 새 포획 Quiz overlay에 1개 적용
2. PC browser 체감 확인
3. 태블릿 WebView FPS / 입력 지연 확인
4. 기존 Three / particle / audio와 충돌 없는지 확인
5. 만족할 경우 도감 등록/탐험 HUD로 확장
6. 월드 내 CanvasTexture 적용은 마지막에 별도 PoC

### 현재 평가

- 시각적 효과: 높음
- Jungle gameplay 적합성: 높음
- 구현 난이도: 낮음~중간
- 기존 Three.js 영향: 낮음
- Android WebView 위험: 낮음 (overlay 방식 기준)
- 우선 적용 가치: **8.5 / 10**

**결론:** 새 포획 Quiz + 도감 시스템과 함께 작은 Canvas overlay PoC로 적용한다.
